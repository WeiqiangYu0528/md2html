# GPT Theme Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship a new standalone `gpt` md2html theme selected with `--theme gpt`, inspired by OpenAI's clean editorial UI while preserving full Markdown feature support.

**Architecture:** Add a self-contained theme folder under `themes/gpt` with its own manifest, stylesheet, Shiki palette, and Mermaid config. The existing theme loader discovers themes by folder, so no parser, renderer, assembler, or CLI code changes are needed. Tests prove the loader sees `gpt`, resolves its custom assets, and keeps desktop-only TOC truncation scoped to the `gpt` theme.

**Tech Stack:** TypeScript, Vitest, CSS custom properties, Shiki theme JSON, Mermaid theme variables. No new dependencies.

**Spec:** `docs/superpowers/specs/2026-06-17-gpt-theme-design.md`

---

## Key facts

- Theme discovery is automatic: `src/themes.ts` lists every folder under `themes/` that contains `theme.json`.
- A standalone theme returns `scopeClass === manifest.name`, so `gpt` renders as `<body class="theme-gpt">` without loader changes.
- Existing theme tests live in `test/themes.test.ts`.
- Existing full-pipeline snapshot coverage uses only the `claude` theme in `test/snapshot.test.ts`; adding `gpt` does not require changing that snapshot.
- The current target Markdown for visual verification is `/Users/connoryu/Downloads/flink_new 3/项目说明.md`.
- Do not stage or commit the existing unrelated `package-lock.json` modification unless the implementation itself changes it.

  it('lists gpt', () => {

    expect(theme.name).toBe('gpt')

    expect(theme.css).toContain('.theme-gpt .md-content')

    expect(theme.mermaid).toBeTypeOf('object')
    expect((theme.mermaid as Record<string, unknown>).themeVariables).toBeTypeOf('object')
